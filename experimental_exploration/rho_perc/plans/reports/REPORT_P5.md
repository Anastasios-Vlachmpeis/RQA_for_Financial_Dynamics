# REPORT P5 — incremental value

**What was run.** Kept transform only (`z`, Decision T in `notebooks/tables/rho_perc/P3/decision.csv`), Article 4 baseline (N = 400 states, m = 3, τ = 7 for F1, 4 for F2, else 1, δ = 0.05, 8-neighbourhood, per-run Theiler rule), unless a task says otherwise. P5a: 11 in-scope processes × 100 runs. Tasks: A, the 501 P3a logistic parameters regenerated at m = 1, N = 1000 (periodic vs chaotic by the sign of λ); B, S3 with vs without a 1.5 sd level shift at a random time in the middle half, 200 runs each; C, F1 with 0.25 sd noise vs an IAAFT surrogate of the same run, 200 pairs (400 rows). Every run has ρ_perc and the full competitor set C (DET, LAM, L, ENTR, K2_lines at RR = 10 %; lag-1 autocorrelation; τ_e; ρ_iso; ρ_lag; ρ_conn = RR over Ω at the largest edge of the minimum spanning tree of D; share of recurrence points in the largest 8-neighbour structure at RR = 10 %) in `notebooks/tables/rho_perc/P5/features.csv` (2,401 rows: 1,100 P5a + 501 + 400 + 400, separated by the `dataset` column). Pre-registered modelling (ridge with StandardScaler and gradient boosting for P5a; standardised logistic regression, 5-fold stratified CV repeated 5 times, ΔAUC interval from 1000 bootstrap resamples of the canonical out-of-fold prediction rows for P5b) is written in `notebooks/tables/rho_perc/P5/spec.json` before the results.

**Gate G5: FAIL — STOP.** The rule (Article 6) needs median unexplained share ≥ 0.20 **and** at least one task whose ΔAUC 95 % interval is above 0. The median held, no task interval did, so `plans/rho_perc/STOP_P5.md` was written by the run and the measure is declared redundant with existing ones. `decision.csv` in `notebooks/tables/rho_perc/P5/` records this from the tables.

**Findings.**

1. Unexplained share (`unexplained.csv`): median U across the 11 processes is 0.5616, above 0.20, but the pooled U (all 1,100 P5a rows, no process indicator) is 0.1009 — most of ρ_perc is explained by C once processes are pooled. Per process, U runs from 0.1004 (F1) and 0.2942 (S3) to 1.0000 (D3) and 0.9701 (F2), so the "unexplained" part is largely process identity, and a high U alone proves nothing (P5 text).
2. Task A (`tasks.csv`): AUC(C) = 0.9991, AUC(C + ρ_perc) = 0.9992, ΔAUC = 0.0001 with 95 % interval [−0.0000, 0.0006]. Best single competitor: K2_lines, AUC 0.9986, next to ρ_perc alone at 0.9604.
3. Task B (`tasks.csv`): AUC(C) = 0.8872, AUC(C + ρ_perc) = 0.8925, ΔAUC = 0.0053 with 95 % interval [−0.0018, 0.0176], which includes 0. Best single competitor: τ_e, AUC 0.8757, next to ρ_perc alone at 0.6279.
4. Task C (`tasks.csv`): AUC(C) = 0.9975, AUC(C + ρ_perc) = 0.9973, ΔAUC = −0.0002 with 95 % interval [−0.0015, 0.0000]. Best single competitor: K2_lines, AUC 0.9870, next to ρ_perc alone at 0.7351.
5. On every task the competitor set alone already reaches AUC ≥ 0.887, and ρ_perc alone is below the best single competitor on all three tasks (`tasks.csv`).

**Deviations.** None. The full run was interrupted once by the harness after all 2,201 cell caches were saved; it was rerun once from those caches (spec unchanged, same version) and completed, with `rhoperc.selfcheck` passing (K1–K9, in `notebooks/tables/rho_perc/P5/run.log`).

**What it means for the paper.** By the pre-registered gate, ρ_perc adds no measured value beyond the existing competitor set on these tasks, so the short methods paper should not be written on this evidence. The honest result is the negative one: ρ_perc is largely explained by known measures (pooled U = 0.1009) and does not improve any of the three classifications.
